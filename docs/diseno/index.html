Referencia visual no negociable del prototipo (entrega 27 nov 2026). Cada pantalla que construyas debe verse como su maqueta. Si algo no cuadra, se pregunta antes de improvisar.

Reglas para todo el equipo

  • Solo tokens. Colores, sombras, radios, espacios y duraciones salen de src/styles/tokens.css. Prohibido escribir un hex, un px de sombra o una fuente nueva en un componente.
  • Solo componentes existentes para lo básico: Button, Input, Badge, .card, OptionButton, PageHeader, Dialog, Icon. Si falta uno, se pide a M0; no se inventa otro parecido.
  • Tipografía: Fraunces solo para títulos h1–h2 y cifras grandes; Noto Sans para todo lo demás.
  • Toque: todo lo tocable mide al menos 48 px (--tap).
  • Lenguaje: de tú, frases cortas. Prohibido para la usuaria: «ruta», «puente», «empleabilidad», «versión», «recursos», «LFPDPPP», «canalización». Siempre «SEMujeres».
  • Zona sensible (asistente, ayuda): solo morados, salida rápida visible y Esc.
  • Aplicación web responsiva: cada pantalla tiene versión de celular (360 px) y de computadora (≥ 960 px), ambas en su maqueta. Sin scroll horizontal.
  • Sin control de tamaño de letra (A−/A+) en ninguna pantalla.
  • Íconos: solo los del componente Icon. Nada de emojis en la interfaz.
  • Accesibilidad: contraste ≥ 4.5:1 (los tokens ya lo cumplen), foco visible, etiquetas en todos los campos.
  • Movimiento: solo con motion y las duraciones de tokens; respeta «reducir movimiento».
  • Clases CSS de tu módulo con prefijo propio (.m3-…) en src/modulos/<tuyo>/estilos.css. No editas CSS global.
